Midnight Apex против Genex

Один и тот же промпт, одна и та же модель (Opus 5.5), примерно одинаковое активное время — около 5,5 часов. Сессия Claude Code сделала игру, которая проходится от меню до результатов и держит 60 fps. Конвейер Genex Studio выдал игру с HUD на треть экрана, пиксельным тахометром и машиной, которая стоит на старте с надписью «STALLED». Разницу целиком объясняет процесс.

1

Кто отвечает за итоговую картинку

Genex
  • Taste-судья сравнивает новую сборку с предыдущей и выбирает лучшую. Вопрос «хорошо ли это» не задаётся.
  • 32 из 35 раундов «выиграли», но satisfied был false во всех 37 итерациях: всегда «лучше, чем было», ни разу «хорошо».
  • Каждый фасет судят на его собственных камерах. Собранную игру целиком на вкус не оценивали ни разу, только проверка «грузится и рисует первый кадр».
Claude Code
  • Ведущий прошёл собранную игру как игрок в 1600×900 по всем камерам и записал 9 конкретных дефектов.
  • Среди них: двоение машины в speed blur, зеркальная машина в асфальте, блики нитро, пар стеной, жёсткий луч фар, засвет белой машины впереди.
  • Каждый дефект ушёл владельцу модуля, затем отдельный агент проверил регрессии.

Правила наказывают полировку

Genex
  • Воркеру: A build that only tunes what already exists LOSES.
  • После двух полировочных побед подряд включается ESCALATE.
  • Большой ход у судьи: Never a tweak, a parameter or one object's finish.
  • Директору: Small fixes are the judge's ledger, never your ladder. Полировка — до трёх необязательных замечаний.
Claude Code
  • Второй этап целиком был полировкой: 4 параллельных полировщика и верификатор, около двух часов.
  • Именно эта работа (сглаживание, отражения, свет фар, детали фасадов) дала разницу на скриншотах.

Метрики-прокси вместо результата

Genex
  • Проверка HUD hud-rich: len(hud.items) >= 60 поощряла рисовать из множества мелких элементов, а vision-проверка speedo прямо просила a segmented tachometer arc.
  • Итог: 6 165–6 551 прямоугольник на кадр, около 600 тыс. заливок в секунду.
  • __studio.state() вырос до 82–90 КБ и обрезался. С середины второй волны все probe-проверки всех фасетов читали обрубок; фикс ed7e7b8 не помог.
  • Принцип шаблона: What cannot be measured does not exist.
Claude Code
  • Автоматические проверки только там, где ответ однозначен: гонка доходит до результатов, fps, ошибки консоли, Node-тесты физики и ИИ.
  • Внешний вид оценивали глазами, по скриншотам в реальном разрешении.

4

Платформа диктует внешний вид

Genex
  • HUD разрешён только внутри canvas через __studio.hud, где есть лишь текст, прямоугольники и прицел. Воркер написал растеризатор из прямоугольников, отсюда лесенки на кругах.
  • Вёрстка в единицах кадра высотой 600 px под окно судьи 960×600, поэтому на любом экране HUD занимает 27–42% и панели наезжают друг на друга.
  • Игра обязана стартовать при загрузке, без меню. Отсчёт идёт сразу, через 9 секунд — «STALLED». Скриптовый заезд судьи попадал в отсчёт, судьи оценивали стоящую машину.
Claude Code
  • HUD на DOM/CSS плюс canvas по реальной плотности пикселей: настоящие дуги, веб-шрифты, анимации, вёрстка в долях экрана.
  • Обычный поток: меню, интро, отсчёт, гонка, результаты, пауза.
  • Отладочный API занимает около 1% кода; стенды для тестов лежат отдельно и в сборку не входят.

Скоуп раздули без пользователя

Genex
  • Отдельный вызов-неймер ещё до планирования придумал название «Midnight Asphalt Pursuit».
  • Контрактор, ничего не спросив, добавил полицию, трафик и шкалу погони.
  • Критик «живости» в каждом фасете просил больше жизни на улицах: вертолёт, блокпосты, радио, музыка, районы, пешеходы.
  • Около 3 000 строк (≈ 11% кода) ушло на погоню, плюс семь разных кузовов машин.
Claude Code
  • Задачу сузили: одна гонка, одна машина героя, четыре соперника.
  • Освободившееся внимание ушло в качество: одна машина с проработанной краской и фарами, физика, ИИ по траектории, звук двигателя.

6

Архитектура и интеграция

Genex
  • Директор разрезал main.js на «системы» с общим объектом состояния; контракта между системами заранее не было.
  • Каждый раунд воркер вливает к себе интеграционную ветку, а ревьюер владения откатывает пришедшие правки. Так hud-2 откатил районы city-2.
  • race-2 удалил камеры, на которых держались чужие проверки. Мигалки вместе с bloom засвечивали кадр в белое, позже кадр стал «молочным».
  • 29 вызовов integrate — около двух часов времени директора.
Claude Code
  • До старта агентов — письменный контракт: API каждого модуля, оси и знаки (курс, руль +1 = вправо, локальные оси машины), владение файлами, рабочие заглушки.
  • Одна точка сборки и один интегратор. Перед полировкой в контракт добавили общий слой рендера, чтобы пламя и частицы не отражались в асфальте.

Цена одной итерации и инфраструктура

Genex
  • Раунд — 22 фазы, 45–135 минут. Бриф 20–39 КБ, заметки обрезаны посреди слова, рецепты подобраны мимо задачи.
  • Восемь окон Electron и восемь сессий Opus xhigh: load average 45–56, около 70 МБ свободной памяти, игра грузится 55 секунд.
  • Падение рендерера в 01:11 потеряло 8 раундов. Финальные исправления убил «harness exited». Большинство фасетов успели 1–4 раунда.
  • По оценке, 35–50% усилий ушло на обслуживание харнесса, а не на игру.
Claude Code
  • Агент сам решал, когда посмотреть на результат: своя стенд-страница модуля и headless Chrome, скриншот за 5–20 секунд.
  • Десятки циклов «сделал — посмотрел — исправил» на агента. Машина тоже была перегружена (load average до 60–90), но цикл не зависел от общего конвейера.

Что у Genex сильнее

  • Автономность. Восемь часов без человека. Сессия Claude Code в ключевой точке опиралась на суждение ведущего: ревью скриншотов и список дефектов.
  • Откат регрессий. Проигравшая сборка откатывается; у сессии Claude Code такого храповика не было.
  • Слепое сравнение A/B и пиксельная статистика, которая численно поймала дрейф яркости.
  • Спайки становятся рецептами. Мокрые отражения вышли настоящей шейдерной техникой.
  • Плейтест. Он нашёл баг ручника, который не видела ни одна проверка. В Midnight Apex живым игроком никто не играл.

Что изменить в Genex

В порядке ожидаемой отдачи.

  1. Финальная фаза арт-директора. Целая игра в реальном разрешении и абсолютный вопрос «отгрузил бы?». Дальше список дефектов, полировщики по владельцам файлов, и полировочному раунду разрешено выигрывать.
  2. Защита скоупа. Контрактор и директор решают, что вырезать, а не что добавить. У экранного пространства и HUD один владелец.
  3. Проверки на результат, а не на реализацию. Убрать счётчики элементов и формулировки, которые диктуют решение, вроде «segmented».
  4. HUD. Разрешить DOM/CSS или дать __studio.hud дуги, пути, изображения и вёрстку в долях экрана. Судить в 1600×900 и выше.
  5. Меню и старт по клавише по умолчанию. Скрипт судьи начинает ехать после старта гонки.
  6. Контракт модулей и заглушки до запуска воркеров. Интеграция волнами, а не на каждом раунде.
  7. Дешевле итерация. Меньше параллельных окон, короче бриф, быстрый цикл «сделал — посмотрел» внутри раунда, восстановление после падения.
  8. Баги харнесса. Уроки из ## Fixed by looking не доходят до следующего прогона: autoApply никто не выставляет. Обрезка state(). Конфликт ревьюера владения с обязательным мержем.
